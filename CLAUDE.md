# MarketPulse — Project Guide for Claude Code

Global stock market web app: live quotes, markets overview, forex, watchlists, paper trading, and a personalized **Daily Market Brief** built from technical signals. Primary data provider: **Finnhub (free tier)**.

## Stack
- **Backend:** Python 3.12, FastAPI, SQLAlchemy 2.x + Alembic, PostgreSQL (SQLite allowed in dev), Redis (cache + rate limiter), APScheduler (scheduled jobs)
- **Frontend:** Next.js (App Router), TypeScript (strict), Tailwind CSS, TradingView Lightweight Charts
- **Auth:** JWT (access + refresh), passwords hashed with bcrypt/argon2
- **Tests:** pytest (backend), Vitest + React Testing Library (frontend)

## Folder structure
```
backend/
  app/
    api/            # FastAPI routers only — thin, no business logic
    core/           # config, security, logging, rate limiter
    providers/      # data provider layer
      base.py       # MarketDataProvider interface
      finnhub.py    # Finnhub adapter (primary)
      fred.py       # FRED adapter (macro)
      fallback/     # approved fallbacks only — twelvedata.py (price history + forex rates)
      registry.py   # maps each capability to a provider; services never name a vendor
    services/       # business logic (markets, portfolio, brief)
    signals/        # indicator math + scoring engine (pure functions)
    models/         # SQLAlchemy models
    schemas/        # Pydantic request/response schemas
    jobs/           # APScheduler jobs (daily brief, symbol refresh)
    ws/             # Finnhub WebSocket client + fan-out to clients
  tests/
  scripts/          # seed_symbols.py, check_finnhub_endpoints.py
frontend/
  app/              # routes
  components/       # UI components (ui/ for primitives)
  lib/              # api client, hooks, formatters
  types/
```

## Finnhub rules (critical)
- Free tier ≈ **60 calls/min**. The app-wide limiter targets **50/min**. Never call Finnhub outside `providers/finnhub.py`.
- **Every** external call goes through: rate limiter → Redis cache → provider. No direct `httpx` calls in services or routers.
- Cache TTLs: quotes 60s · news 15min · profiles/metrics 24h · symbol lists 7d · market status 5min.
- **One** shared backend WebSocket to `wss://ws.finnhub.io`. Subscribe only to symbols users are viewing or watching; unsubscribe when no one needs them. Fan out to the frontend via our own WebSocket/SSE. Never open a Finnhub socket from the browser (it would expose the key).
- Endpoints that return 403/premium on the free tier are listed in `docs/finnhub-endpoints.md` (generated by `check_finnhub_endpoints.py`). Check that file before using an endpoint. Don't assume.
- On 429 or provider errors: back off, serve cached data with an `as_of` timestamp, and never crash a page.
- **Free-tier gaps (checked 2026-10-19):** no candles, no non-US quotes/symbol lists, no index (`^GSPC`) or forex quotes, no `/forex/rates`, no `/news-sentiment`. Price history and forex rates come from **Twelve Data** (approved fallback; 7/min and 750/day limiter). Twelve Data's free plan also excludes NSE and other non-US equities. Global indices are shown as US-listed ETF proxies (e.g. INDA, EWJ, VGK), labelled as ETFs. News sentiment is a keyword score over headlines.
- Symbol directory is seeded into the DB once. Search hits the DB, not Finnhub.

## Secrets & config
- All keys live in `.env` (gitignored). Keep `.env.example` updated with every new variable.
- Vars: `FINNHUB_API_KEY`, `TWELVEDATA_API_KEY`, `FRED_API_KEY`, `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`, optional `LLM_API_KEY`, `SMTP_*`.
- Never log, print, commit, or return an API key in a response. Never put keys in frontend code or `NEXT_PUBLIC_*` vars.
- **Auth model:** 15-min JWT access token kept in memory only (never localStorage); rotating opaque refresh token in an httpOnly SameSite=Lax cookie scoped to `/api/v1/auth`, stored hashed. Reuse of a rotated token >30s after rotation revokes all the user's sessions. Protected routes use the `CurrentUser` dependency; every watchlist/portfolio query is scoped to the owner (other users' resources return 404).
- **Paper trading:** Decimal math in `services/portfolio_math.py` (pure). Orders use optimistic concurrency on `portfolios.version` (works on SQLite and Postgres); refuse orders on stale quotes. After `session.rollback()` re-load objects explicitly (`await session.refresh(...)`): lazy loads crash in async code.

## Coding conventions
- **Python:** type hints everywhere, Pydantic for all I/O, async I/O (`httpx.AsyncClient`), format with `ruff format`, lint with `ruff check`.
- **TypeScript:** strict mode, no `any`, server components by default, client components only when interactivity is needed.
- Routers stay thin; logic lives in `services/`; indicator math in `signals/` stays pure (no I/O) so it's easy to test.
- Money and prices: use `Decimal` in Python for portfolio math; format with locale-aware formatters in the UI. Always store currency alongside price.
- Times: store UTC, convert to user/exchange timezone only for display. Market hours use the exchange's own timezone.
- Every data-driven UI shows: loading skeleton, empty state, error state, and "data as of HH:MM" when cached.
- Next.js 16 with Cache Components: read `frontend/node_modules/next/dist/docs/` before using an unfamiliar API (see `frontend/AGENTS.md`). Server components fetch inside `<Suspense>`; live prices come from one shared SSE stream per page (`LiveQuotesProvider`), never one per widget.

## Daily Market Brief — non-negotiables
- Signals are **labels with reasons** ("Bullish signals: RSI 28 oversold, price above 200-DMA"), never bare "BUY/SELL" commands.
- Every brief and signal view shows: *"Educational information based on technical indicators, not financial advice."*
- Brief jobs spread API calls over time to stay under the rate limit. Never fire a burst for all users at once.
- Store each generated signal so the Signal History page can measure past performance.

## Workflow
1. For any non-trivial task: read relevant files first, propose a short plan, then implement.
2. Work in phases. After each phase: run tests + lint + typecheck, fix failures, commit with a clear message, and tell me what to test manually.
3. Write or update tests with every feature. Mock Finnhub in tests; never hit the real API in the test suite.
4. Ask before: adding a new dependency, adding a new data provider, changing the DB schema in a breaking way, or deleting files.
5. Keep changes focused. Don't refactor unrelated code in the same change.
6. If something is ambiguous, ask one specific question instead of guessing.

## Don'ts
- Don't hardcode symbols, keys, or prices (except in tests/fixtures).
- Don't poll Finnhub REST for live prices when the WebSocket can provide them.
- Don't add a paid API or a scraping approach.
- Don't silently swallow errors. Log them with context and surface a friendly message.
